THE PROBLEM02 / 34
Context

浏览器已经是个人计算环境。

越来越多的状态

标签页、窗口、标签组、书签、扩展逐渐形成个人工作环境，而不是简单的“网页浏览记录”。

跨设备却不一致

换电脑、换系统、重新安装浏览器时，真正需要恢复的是“工作现场”，而不是一个抽象的账户。

云同步缺少控制感

传统方案通常把同步边界交给服务商；而本项目把同步存储边界放到了用户自己的 GitHub Gist。

冲突比丢数据更危险

两个设备都改了内容时，盲目覆盖会制造隐蔽的数据丢失，因此系统必须保留基线、合并与冲突记录。

从“浏览器同步”重新理解“个人状态管理”02
THE IDEA03 / 34
Core Thesis
不是把浏览器“上传到云端”，而是让浏览器状态有一个你能理解、检查和恢复的公共快照。

同步数据采用普通 JSON 结构，GitHub Gist 提供远端边界与 revision history；本地浏览器保留基线与同步元数据，合并逻辑独立于 UI。

Local State × Base Snapshot × Remote State03
WHAT IT SYNCS04 / 34
Scope

同步边界明确，避免“什么都想同步”。

01
Tabs & Windows

普通窗口、HTTP(S) 标签页、顺序、置顶、激活状态与窗口状态。

02
Tab Groups

标题、颜色、折叠状态，以及稳定同步身份。

03
Bookmarks

使用 syncId 而不是依赖不同设备的本地 bookmark ID。

04
Extensions

扩展元数据、启用状态、版本、主页与更新来源等。

明确不做：第三方扩展设置

第三方扩展拥有隔离存储，通用同步扩展无法安全地读写其他扩展的私有 storage。因此本项目把“扩展库存”与“扩展设置”作为两个不同问题。

Scope is a feature.04

SYNC MODEL06 / 34
Three-way Merge

核心不是覆盖，而是比较。

Base

设备上一次成功同步后的共同基线。没有基线，就无法知道“谁真正改过”。

Local

当前浏览器实时收集出的状态。包括 tabs、bookmarks、extensions 等。

Remote

当前 Gist 中的共享状态。与本地状态同时参与决策。

Merge Policy

Local 与 Remote 都未偏离 Base → 可直接采用；只有一侧变化 → 采用变化侧；双方同时变化 → 按字段策略合并或记录冲突。

Base is what makes “change” observable.06
MERGE POLICY07 / 34
Field-level Resolution

不同字段，不应该用同一种冲突策略。

latest

例如 title、enabled、collapsed 等字段，比较 updatedAt，以较新的值作为自动决策。

maxVersion

扩展版本字段使用版本元组比较，避免低版本覆盖高版本。

conflict

对于 URL 等更敏感字段，双方都发生变化时保留冲突，默认不强行替用户选择。

device-live-state

Windows 作为当前设备运行时状态，复杂同时修改时保留本地为实际结果并留下已解决记录。

Policy belongs to the data shape.07
TOMBSTONES08 / 34
Deletion Semantics
DELETE ≠ FORGET

删除不能只是从数组里移走对象。系统需要记录“这个对象曾经存在，并在什么时候被删除”，否则另一个设备上的旧副本可能再次把它复活。

Tombstone

{ collection, syncId, deletedAt, revision }

Stale copies must not resurrect deleted state.08
IDENTITY09 / 34
Stable Sync IDs

本地 ID 不等于同步 ID。

Tabs / Windows / Groups

Chromium 在不同设备上分配的 localId 不稳定，因此项目维护持久化映射，把本地 ID 映射为随机 UUID 派生的 syncId。

Bookmarks

书签同样不依赖跨设备一致的 Chrome bookmark ID，而是建立自己的同步身份与 parentSyncId 结构。

这使跨机器 merge 可以比较“同一个实体”，而不是比较“两个恰好数字相同的本地对象”。

Identity survives device boundaries.09
BOOKMARKS10 / 34
Normalization

书签被扁平化成可合并的实体集合。

syncId

实体稳定身份。

parentSyncId

表达层级关系，而不是依赖浏览器本地节点 ID。

index

表达同级排序。

title / url

核心内容字段，分别参与字段级合并。

这种标准化是同步系统可解释性的关键：远端 JSON 不只是“备份文件”，而是可被 merge engine 理解的数据模型。

Normalize first. Merge second.10

Extension Inventory

先知道“我应该有哪些扩展”。

Metadata

id、name、version、enabled、description、homepageUrl、updateUrl、installType。

Store hints

PACKAGE INTEGRITY14 / 34
Integrity, not Encryption
SHA-256

第三方扩展包的 hash 用于完整性元数据验证。它回答的是“这个文件有没有变化”，而不是“这个文件是不是加密的”。

What it helps

发现传输或存储过程中的内容变化。

What it does not

不提供端到端加密，也不替代访问控制。

Integrity ≠ Confidentiality14
GIST MODEL15 / 34
Remote Storage

一个 Private Gist，两个关键文件。

manifest.json

schemaVersion、format、currentFile、revision、lastUpdatedAt 等同步元信息。

current.json

当前完整同步 state：snapshot、tombstones、conflicts、revision 等。

Legacy compatibility

旧的加密 current.enc.json 与 legacy Gist 结构仍可读取，系统会归一化到当前 schema。

Current state is inspectable JSON.15
REVISION SAFETY16 / 34
Write Verification

写进去，不等于写成功。

Revision

单调递增的 revision 让更新顺序可解释。

ETag

保存远端 ETag，减少无意义重读，也为并发更新场景提供信号。

Checksum

远端读回后比较 snapshot checksum，确认真正写入的是预期内容。

Retry with a ceiling

GitHub API 会有限次数重试；反复并发失败不会无限循环写入。

Write → Verify → Advance16
HISTORY17 / 34
Recovery Points

历史记录不是装饰，是安全网。

30 recent entries locally

本地维护最近最多 30 条历史索引，用于快速查看同步轨迹。

Remote Gist revisions

GitHub 自己提供远端 revision history，可继续向更早状态回溯。

Rollback creates a new revision

回滚不是把历史伪装成当前，而是用旧 snapshot 生成新的 current revision。

Conflicts stay inspectable

历史页同时呈现 unresolved conflicts，避免“为了同步成功而抹掉问题”。

Rollback is an operation, not a time machine.17
CONFLICTS18 / 34
Conflict Visibility
好同步系统，不是没有冲突，而是冲突不会悄悄消失。

field-conflict

双方对同一字段产生独立修改，需要人工查看。

delete-vs-modify

一侧删除、另一侧修改同一实体时，作为显式冲突记录。

array-conflict

无法识别实体身份的数组不被冒险合并，而是记录冲突。

Visibility beats silent data loss.18
CONFLICT CLEANUP19 / 34
Normalization

记录冲突，也要避免“脏状态永久堆积”。

resolved / ignored → filtered

历史中已解决或忽略的冲突不会继续阻塞当前状态。

Meaningful values only

空对象、空值型噪声不会被当作真正冲突。

为什么重要

冲突系统本身也是状态系统。只有把“当前真正需要处理的问题”与历史噪音分开，用户才能持续信任同步中心。

Conflict state needs lifecycle management.19

SECURITY22 / 34
Trust Boundary

项目的安全边界，是“知道自己没有做什么”。

Private Gist

新建同步 Gist 默认 private。

Token stays local

GitHub Token 与 Gist binding 保存在浏览器本地 storage，不进入同步快照。

WebDAV credentials stay local

WebDAV 凭据不写入远端同步数据。

Current JSON is not E2E encrypted

当前 current.json 是普通 JSON。旧加密格式仍可兼容读取，但新状态不再伪装成“端到端加密”。

Security claims remain bounded.22

TESTING27 / 34
Regression Safety

同步系统最怕“看起来能用”。

npm test

运行 sync-core 回归测试，覆盖本地变化、tombstone、字段冲突、相同变化收敛等路径。

npm run validate

RELEASE28 / 34
Stable vs Dev

manifest.version_name

LIMITATIONS31 / 34

WHAT COMES NEXT32 / 34
Roadmap Direction

Browser settings

Extension settings
