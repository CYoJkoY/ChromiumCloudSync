User Guide

A local-first Chromium sync tool backed by GitHub Gist.

Quick start

Open Settings, enter your GitHub Token, validate it, then create a new private Gist or bind an existing one. After that, use Sync now or enable automatic synchronization.

Popup overview

The popup shows synchronization readiness, the current Gist, the last successful synchronization time, automatic-sync status, revision and conflict counts, and actions for syncing or restoring browser data. The popup also hides third-party package backups when that feature is disabled.

What is synchronized

The shared sync state can contain open tabs and windows, tab groups, bookmarks, installed extension metadata, selected extension-local storage, device identity information, synchronization metadata, deletion tombstones, checksums, and conflict records.

The current synchronization payload is stored as normal JSON in the Gist. The repository retains compatibility code for older encrypted Gist formats, but current synchronization should not be described as end-to-end encrypted.

Device identity

Each browser can have a user-defined device name such as “Home PC”, “Work Laptop”, or “Gaming Browser”. The name is used as the logical device identity during synchronization and is saved locally before being included in the next successful sync.

Sync model

The sync engine keeps a local base snapshot and performs a three-way merge between base, local, and remote state. Stable synchronization IDs are used for tabs, windows, groups, and bookmarks. Deletions are represented by tombstones so removed items do not silently reappear. Conflicting field changes can remain visible for manual resolution.

Automatic sync

Automatic synchronization is disabled by default and uses a five-minute interval by default. In Settings you can enable it and select 5, 10, 15, 30, or 60 minutes. Browser events only trigger background synchronization when automatic sync is enabled.

Third-party extension backups

CRX and ZIP packages for extensions installed outside a browser store use a separate optional file-backup system. The available backends are Disabled, GitHub private repository, and WebDAV. When Disabled is selected, the GitHub repository, branch, folder, WebDAV credentials, connection controls, and explanatory storage notes are hidden, and the popup does not show the third-party backup card.

With GitHub private repository selected, only the GitHub repository, optional branch, and storage folder settings are shown. With WebDAV selected, only the WebDAV URL, folder, username, and password are shown.

Package backups are uploaded only after the user explicitly selects a CRX or ZIP file. GitHub Contents API uploads above 95 MB are rejected. Package installation always remains a manual browser action.

History and rollback

GitHub Gist keeps the revision history for the synchronized state. The extension also keeps a local history index with up to 30 recent entries. The history page can inspect revisions and roll a selected version back as a new current revision.

Settings pages

The Settings page is divided into Sync, Third-party extensions, and Local areas. Sync contains GitHub connection and automatic-sync controls, Third-party extensions contains package-backup configuration, and Local shows the current local status.

Privacy

New sync Gists created by the extension are private. GitHub access uses your own Token. The current sync state is stored as JSON, so access to the Gist should be treated as access to the synchronized browser data. Third-party package backups use the separate backend you configure.

Troubleshooting

If an older Gist uses a removed encrypted format, use a compatible older release to migrate it successfully. For current settings problems, reload the extension after an update and verify that the selected storage backend and GitHub credentials match the configuration shown in Settings.
